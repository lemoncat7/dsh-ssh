# 1.19.2

修复传输任务取消后仍停留在「传输中」的问题，包括连接已关闭但协议回调没有返回的情况。

- 服务端取消会关闭任务独占的两端连接、结束工作并释放传输名额；HTTP 与 AI 工具返回确认后的最终状态，不再把收到取消请求当作已经停止。
- 补齐连接建立、目录扫描和文件传输的取消处理，清理部分成功或延迟完成的连接，防止任务或连接遗留。
- 浏览器上传支持取消，取消当前文件后停止批次中的后续文件；延迟到达的进度和完成事件不会恢复已取消的记录。
- 浏览器流式下载在等待保存选择器、创建写入器、读取或写入期间均可取消；最后提交本地保存时显示明确提示，完成后可关闭记录。
- 服务端任务取消期间显示「正在取消」，请求失败可重试；旧的轮询响应不会覆盖取消结果。完成、失败或取消的任务均可关闭记录，冲突任务仍保留处理入口。
- 浏览器原生下载明确提示在浏览器下载列表查看进度或取消；关闭插件中的记录不会停止原生下载，也不会删除下载文件。

验证：319 项完整测试、6 个加载生产样式并调用本地 HTTP 接口的浏览器场景全部通过；部署后使用已安装代码通过 26 项取消与下载回归测试，服务健康检查及渠道恢复检查通过。浏览器检查使用隔离端点，不访问真实主机或覆盖用户文件。现有主机、目录、凭据及权限配置无需迁移。

安装或升级后重启对应的 DSH Profile，并刷新浏览器页面。
